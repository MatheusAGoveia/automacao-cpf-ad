# CPF no Active Directory — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Preencher exclusivamente o atributo CPF vazio de usuários já concluídos no CSV.

**Architecture:** Script PowerShell com importação de CSV e módulo de regras testável com adaptadores de AD. Configuração JSON associa os rótulos dos domínios a servidores explícitos. A execução padrão simula; `-Aplicar` grava e verifica a leitura posterior.

**Tech Stack:** Windows PowerShell 5.1+, módulo ActiveDirectory, JSON e CSV; testes locais sem rede.

**Spec:** Regras confirmadas nesta conversa: CSV baixado, colunas NOME COMPLETO/DOMINIO/NOVO LOGIN/CPF/CONCLUÍDO; apenas concluídos com CPF; comparar nome e login; preencher CPF vazio; preservar CPF existente. Servidores ainda desconhecidos ficarão configuráveis. Decisões de implementação: simulação padrão, rejeitar CPF inválido, pular ações como desativar, nome sem login somente com correspondência única, nunca alterar nomes/logins/status da planilha.

## Global Constraints

- Nunca substituir CPF já preenchido.
- Nunca escrever em linha não concluída ou sem CPF.
- Nenhuma consulta ao AD real durante testes.
- Nenhuma credencial salva no projeto; usar sessão Windows.
- Servidores desconhecidos não podem ser inferidos.

## Review Focus

- CSV do Google pode incluir título antes do cabeçalho, BOM, delimitador vírgula/ponto e vírgula e zeros à esquerda.
- Homônimos, login divergente e filtros LDAP com caracteres especiais precisam impedir seleção incorreta.
- Dois CPFs diferentes para o mesmo objeto devem bloquear ambas as linhas antes de gravar.
- CPF que apareça entre planejamento e gravação deve ser preservado; usar Add em atributo comprovadamente de valor único.
- Erro de rede/gravação deve aparecer no relatório sem transformar falha em sucesso.

## Validação

19 cenários passaram em Windows PowerShell 5.1 e PowerShell 7.6.3, usando dados fictícios e adaptadores/comandos AD falsos. Revisão independente encontrou conflito entre controladores para o mesmo objeto e um padrão amplo no gitignore; ambos corrigidos. O teste de regressão reproduziu o conflito e passou após agrupar exclusivamente pelo GUID. Nenhum acesso ao AD real foi realizado. Faltam servidores e CSV reais para a validação no ambiente do usuário.
